## <a id="r022"></a>022 公开 API 冻结

- 决策状态：已定（待定项见文末）

### 1. 面在哪

- 下游只有一条 import 路径：`oncasket.api`（见[包与目录 §031](packages.md#r031)）。
- **公开类型长在公开面上**：名字在 [`api/__init__.py`](../../src/oncasket/api/__init__.py)
  里定义或重导出、逐个进 `__all__`。私有类型不许出现在公开签名里——它的 `__module__`
  会跟着 repr 漏出去（`oncasket._ops.write.Handle` 就是这么漏的）。
- `api/` 可以往下长**公开子模块**（`api/index.py` 这种），子模块自己也有 `__all__`；
  顶层白名单不因此变长。
- 由此有一条**推论**（不只是风格）：公开对象只装内容、不碰盘；读写一律经 `_ops`。
  方向永远是 `api` → `_ops`，与[依赖分层表](packages.md#r031)同向，不成环。

### 2. 三段

下游做一件事分成三段——这是设计给的分界，不是实现细节：

| 段 | 谁做 | 手上有什么 | 出处 |
|---|---|---|---|
| ① 声明 | 下游 | 纯内存：块 id、角色、属性、块体；可重复算 | [索引库 §009](index_db.md#r009) ①、[格式 §3](format.md#r021) |
| ② 提交 | 引擎 | 索引行、park、槽地址 | §009 ②–⑦ |
| ③ 读回 | 引擎 | 地址 → 内容（逐槽 `check` 已验过） | [格式 §9](format.md#r021) |

- **地址是结果，不是入参**：`park` / `first_slot_id` 是 ② 的产物，声明段拿不到、也不该拿。
- 内部实现已经长在这个分界上：`plan_block`（内容）→ 物理写 → `parse_block`（读回）。
- ②③ 各有**两套入口**：默认一口气的那条（§10 / §11），以及把流程摊开的拆解版
  （默认不开放，自己不担保）。剩下没定的是签名，见待定 2。

### 3. 草案里的名字对盘

| 草案里的名 | 是什么 | 出处 |
|---|---|---|
| `Block` | 一条链：头槽\* ＋ data 槽\*，不跨 park | [格式 §3](format.md#r021)、§5 |
| `Block().id` | `block_id`：uuid4、128 位、头槽自述区第 0 项，**引擎生成** | [格式 §3](format.md#r021) |
| `Block().ref` | **角色／表归属**：数据型还是索引型；取值是字符串 | [索引库 §006](index_db.md#r006) |
| `Block().attr` | 自述区**属性字典**：名唯一、按名 utf-8 升序、条目不可分割 | [格式 §3](format.md#r021) |
| `Block().body` | `block_body_size` 位的那段字节 | [格式 §3](format.md#r021) |
| `Hub("hub")` | 入口：一个 hub 的句柄（索引库、park、锁都在它手里） | [hub 布局 §005](hub.md#r005) |
| `Pack(block)` | 把块打成物理槽序的那一层：`check` / `allocate` / `write` / `sync` | [格式 §7](format.md#r021) |
| `Body().type` | **块体类型声明**：读端靠它推理怎么解，不是盘上的一格 | [格式 §3](format.md#r021) |

### 4. 角色：字符串流转，不校验，索引型是预制菜

- `Ref` 管的是**角色**：这个块是数据型还是索引型。`Ref.data` 只是拿一个**预制属性**，
  `Ref("data")` 自己传字符串，等价：**全程字符串流转，不做枚举**——与 §006 里
  「`kind` 开放取值、不枚举、不加 CHECK」是同一个口径。
- **不做取值校验**：字符串让它流过去，打错字是调用方自己的事，引擎不替调用方认字。
  这不是「放开一道检查」，是**根本不立这道检查**——没有枚举，就没有「非法取值」这个概念。
- **索引型两种来路**：引擎把 `AttrIndex` / `BodyIndex` 造好（预制菜），下游**也可以自己造索引块**
  （§8 末）——引擎不拦。角色取值不校验，字符串是什么就是什么。
- `Ref` 与 `kind` 的分工：`Ref` 是角色标签，`kind` 是「装了什么 / 索引了什么」——两者都开放。

### 5. 属性：身份就是一条 KV，锁是可变性开关

- 属性为什么不是裸 `dict`：**「可自定义」本身就是一套行为**——按名升序落盘、单条上限、
  以及「谁能改到哪一步」，都要有地方挂，所以要有专门对象。
- **`Attr(owner, name)` 的身份就是一条 KV**：字典结构必然有键有值，`name` 就是那个键——
  没有键，值无处可挂；`owner` 是它挂在谁身上。
- **锁是可变性开关，不是并发锁**：`attr.lock.all()` 之后整个属性区不可改，`attr.lock.item()`
  之后那一条不可改——语义同 dataclass 的 frozen：**它是不可变数据这件事本身**。
  声明段是纯内存对象，不存在要防的并发写者。
- 两个锁**形态一致**（都是「取子对象再调用」），不再长短不一：原草图的 `lock("名")`
  统一成 `lock.item(名)`。

### 6. 块体类型：给读端推理用的，登记在 hub 级清单里

- `body.type` 是**类型声明**：data 槽里的字节就是 Python 原生结构落下来的那一份，
  **不知道类型就解不回来**——声明它，读端才不必盲猜这是 list、dict 还是 string。
- 它不给自己在块的字节里占一格（盘上 body 只有 `block_body_size` 位字节），而是**登记**在
  hub 级清单里：按作者口径，`hub.lock.json` 记着每个块、每个属性、每个 block 的类型——
  **写端负责登记，读端从那儿取**。
- 这份登记本身就是**为迁移设计**的：换一套代码读老数据，靠的就是它。
- 登记落在锁文件还是清单文件，见待定 1。

### 7. 句柄就是读写通道

- 读写**本质上是持有句柄**去动它：持有 `body` 句柄写块体，也可以持有**属性句柄**读写。
- 没有限制说「属性不能当块体用」：完全可以，只是大多数时候没必要（有点神经病）。
  **特化场景就正好合适**——索引这种东西天然就是一层 KV，拿属性当它的载体是顺手的。
- 与 §5 的锁合起来读：句柄只在锁之前有效；锁之后只能读。

### 8. 原生索引：索引块就是索引，库里不检索

库里只放**身份、地址、状态**（`block` 的八列与两条索引，见 [`config/index_db.sql`](../../config/index_db.sql)），
**不给用户属性建任何库侧索引**。要按属性或块体反查，走**索引块**——这就是「两种块」存在的理由：

| 块 | 装什么 |
|---|---|
| 数据块 | 用户的内容（属性 ＋ 块体） |
| 索引块 | 「谁在哪」：键 → `block_id` 的对照 |

- 索引块**就是块**，所以它跟着载体走：占槽、提交、被盲扫、可重建（[§013](index_db.md#r013)）。
  这是立第三张表做不到的——那就等于把索引另立成与载体并列的第二份真相。

#### `open()`：手动开，不开就不索引

**索引不会自己长出来**：不手动 `open`，这两个索引块压根不会收你的东西——跟数据库里不建索引
就不处理查询是一个道理。`open` 是唯一的开关，属性与块体各有各的。

**属性那边：`open` 之后默认全量，一旦 `set` 就只听 `set` 的。**

- 一个 `set` 都不调 → 这个块的**全部属性**都进索引；
- 调了 `set` → 只索引点过名的那些，**其余一个都不进**（12 个属性里 `set` 了 3 个，
  剩下 9 个全都不索引）。
- **不做「纯排除」写法**：想索引 12 个里的 11 个、只排除 1 个，这种需求本身不成立，不支持——
  要么不 `set`（全量），要么点名。

**块体那边：`open` 之后，写入时主动留存一份正文。**

- 留存的是**纯正文**：剔掉所有非正文部分（填充等），对**完整正文**算一个哈希，按哈希留存；
- 没有 `set` 这样的点名机制，`open` 就是全部。

```python
self.attr.index.open()
self.attr.index.set("title", only_one=bool)  # 点名 title；不 set 就是全量

self.body.index.open()  # 写入时留存一份纯正文，按正文哈希建索引

from oncasket.api.index import AttrIndex, BodyIndex

aix = AttrIndex()
block_id = aix.search("")  # 按属性取值反查
title = self.attr.get("title").item()
block_id = aix.search(title)

bix = BodyIndex()
body = self.body.get().hash()  # 纯正文的哈希
block_id = bix.search(body)
```

- **一个键后面挂几个 `block_id`**，属性与块体**共用同一个开关** `only_one`：

  | 索引 | 键是什么 | `only_one=False`（默认） | `only_one=True` |
  |---|---|---|---|
  | `AttrIndex` | 属性取值 | 一个取值挂一**串** `block_id` | 该取值全局唯一：只许一个 |
  | `BodyIndex` | 正文哈希 | 理论上一个正文对应一个块，但**完全重复的正文只留存一份**，一个哈希下挂多个 `block_id`——这就是内建的去重方式 | 严格一一对应 |

- 原来那对 `no_one` / `only_one` 砍掉了 `no_one`，块体侧的两个开关也并成一个 `only_one`：
  一个布尔就没有「两个都关 = 悬空」的薛定谔状态，意思更明确。

- **索引的产物只有一样：`block_id`**。拿到 id 之后就没有难事了——地址在库里、
  内容在载体上，读回走 §2 的正常那条路。
- `AttrIndex` / `BodyIndex` 是 `oncasket.api.index` 的公开名字，是**引擎原生只提供的两种**。
- **其余索引块随便造**：想索引别的东西就自己造索引块，引擎不拦——逻辑本来就是确定的
  （拿到 `block_id` 之后按你自己的数据结构去查），自由度给了就不必再管。
  这两种原生索引的特殊之处只在于「引擎替你把它造好了」。
- 索引块**分两层**：门面上给你的是 `AttrIndex` / `BodyIndex` 两个，底下一大堆**子索引块**
  （它自己又索引了一批 block）。块有上限，装满了必然要增量——所以你不是"直接锁到"目标块，
  而是一层层锁下去，**但总共就两层**。
- 根入口在哪见待定 3。

### 9. block_id：引擎生成，不给指定入口

- `Block()` 出来就带 `id`，**不提供**调用方指定 id 的入口。
- 要自己的身份就自己存：放进 `attr`，**再给那条属性开索引**（`attr.index.open()`），
  之后 `AttrIndex.search(你的 id)` 照样拿得到 `block_id`。代价是写入更贵（多一条索引路径），
  而不是「没有路」。
- 与重建不矛盾：生成的 id 本身就在头槽自述区里，[§013](index_db.md#r013) 由载体读回。

### 10. 写入：默认一口气，拆解版默认不开放

**默认只有一条路**——把块交给 hub，整条流水线（[索引库 §009](index_db.md#r009) ②–⑦）一口气走完：

```python
self.h = Hub("hub")
self.h.write(self.b)
```

- 按**固定流程**走，引擎担保；出问题是引擎的事。这就是 022 默认开放的**全部**写入面。
- **拆解版**（默认不开放）把流程摊开，每一步自己调。**按你自己的写法走，引擎不担保**：

```python
self.h = Hub("hub")
self.p = Pack(self.b)
if self.p.check() is True:
    if self.p.allocate(self.h) is True:
        self.p.write(self.h)
    else:
        self.p.re_allocate(self.h)
        self.p.write(self.h)
    self.p.sync(self.h.index.db)
```

- 上面这组只是**形状**：不同流程有不同的一组 API，具体名单见待定 2。

### 11. 读取：也是两条腿

- **一口气**：直接拿到内容，地址那一层不用你操心。
- **拆解版**：`库 → park → block → body` 一层层取——繁琐，但每一层都在你手上。

两条腿与写入侧是同一个设计：**默认那条担保，拆解那条自便**。

### 12. 草案里的笔误（demo 随手写的，已就地改掉）

| 雏形里的写法 | 问题 | 现在 |
|---|---|---|
| `from oncasket.block import …` | `oncasket/block.py` 不存在、也不允许——顶层白名单只有 `py.typed` 与 `api/` | `from oncasket.api import …` |
| `def init_attr(self):` | 缺返回注解（本仓所有函数都要） | 补 `-> Attr` |
| `def init_body(self) -> None:` 却 `return body.type.set(list)` | 注解与返回不一致 | 拆成调用 ＋ `return body` |
| `self.b.attr.set(...)` 调了两次（`init_attr` 内一次、`__init__` 里又一次） | `set` 到底是「装进去」还是「读回来」 | 一句「装进去并返回句柄」就够，与 §6 的句柄走同一条路 |
| `attr.lock("item")` | 与 `lock.all()` 长短不一，且没带参数 | 统一成 `attr.lock.item(名)` |
| `attr.index.set(name, no_one=…, only_one=…)` | 两个开关会打架（都关就悬空） | 砍掉 `no_one`，只留 `only_one`：一个布尔没有悬空态 |
| `self.Hub("hub")` | 类名写成实例属性 | `Hub("hub")` |
| `Pack(self.b)` | 与盘上的 **park**（那个 `.oncat` 文件）只差一个字母，公开面里两个近名概念迟早咬人 | 名字未定，见待定 2：`Pack` 这一层干的是「把块打成物理槽序」 |

### 13. 已经对的地方

- **组合，不是继承**：`self.b = Block()`，下游持有块、不继承块——块是数据，不是类型。
- **角色与类型都走字符串**：不枚举、不加 CHECK，加一种「装了什么」不用改类、不用发版。
- **声明与提交分开**：草案停在声明段，没有把地址塞进构造函数。
- **id 由引擎给**：下游不参与身份生成，也就不会撞 id。
