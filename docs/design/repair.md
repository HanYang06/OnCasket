# 修复：先修再判坏、异常分内外、修复只出编号

> 域：内核 / 存储引擎 / 故障处置。对应路线图 [1.x 路线增量](../roadmap/1.x.md)。
>
> **事实依据**：[`config/repair.txt`](../../config/repair.txt)——**修复清单以它为准**，本文不另立、不改。
> 规范见[文档规范](../README.md)。

## <a id="r032"></a>032 修复规范：先修再判坏与编号清单

- 决策状态：已定（待定项见文末）

### 1. 总则：先修，修不了才算坏

盘上的状态不对，当场**分不清真坏假坏**——那就先修一把：修好了就是假坏，修的途中又出问题、
或者压根没有适用的修复，才判它坏。修飞机、修摩托、修汽车都是这个路子。

1. **异常先过修复清单**：读不满、计数不自洽、孤儿槽、索引与载体对不上……都先找修复，**不直接判坏**。
2. **一条修复只管自己**：只认自己的触发、只做自己的动作，不调用别的修复、不假设别人跑过。
3. **修完必须复检**：复检不过 = 没修好 → 换下一条；所有适用的都试过还不行，才判坏。
   判坏要**出声**——静默丢弃数据是不可接受的。
4. 判坏的**落点按症状定**：park 级不再使用它、另起新 park；hub 级拒开。但**判坏永远是最后一步**。

### 2. 异常分两类：外部与内部

| 类 | 谁上报 | 有没有后续动作 |
|---|---|---|
| **外部异常** | 直接呈报调用方（抛出去） | 没有——修不了，也不该瞒着 |
| **内部异常** | 先记进日志（引擎内部） | **跟着做修复**；修完复检，修不动才升级成外部异常 |

- 分界的判据只有一条：**引擎手里有没有治得了它的修复**。有 → 内部；没有 → 外部。
- 「版本类」是外部异常的典型：另一套位布局，引擎没有修法（见 §5）。
- 调用方拿到的**永远只有外部异常**；内部异常在日志里只留编号，不在异常里带症状。

### 3. 修复两条来源，一种性质

| 来源 | 什么时候发生 |
|---|---|
| **内部异常触发** | 异常报出来之后跟着做 |
| **自动型** | 不靠异常触发：轮次到了就做（如 GC 轮次里的计数校正） |

- **两条来源、一种性质**：一条修复就只有四样东西——**编号、触发、复检、落点**。
  不为来源不同分等级、分类型，也不因为来源不同就有不同的日志形态。
- 自动型不是例外：照样登记、照样复检、照样只出编号。

### 4. 修复只出编号，不出症状

- 一条修复一个**编号**：`R` ＋ 三位数字（`R001`、`R002`…）；**只增不减、号不复用、全仓连号**。
  新修复接在末尾发新号；改描述不改号；与路线ID同一套规矩。
- **不用名词命名**：日志里只出现编号，**不复述哪里坏了**。编号的含义只活在
  [`config/repair.txt`](../../config/repair.txt) 这一处对照表里——对外只暴露「修过第几号」。
- **静默 ≠ 无痕**：修复一经发生就要经日志接口（路线 022）留痕，只是痕迹里只有编号；
  改盘的动作用编号留痕，是事后唯一能复盘的东西。
- 对照表与日志是两回事：`config/repair.txt` 里当然写清楚每条治什么、怎么复检，
  但那是仓库里的账，**不进日志、不进异常消息**。

### 5. 版本类没有修复

- park 头 `version`（[格式 §2](format.md#r021)）是**格式事实依据的指纹**，不是数据指纹：
  数据写坏不会让它变；它答的是「按哪一版 `format.txt` 写的」。
  所以它不符只可能是两件事：**版本变了**（升级／降级），或**有人动过**。
- 版本不符**不进修复清单**：那是另一套位布局，猜不得。处置是**拒开**并**报出怎么修**——
  指到仓库里的版本迁移脚本，跑完再来（落点见待定）。
- 索引库 schema 指纹不符（[索引库 §012](index_db.md#r012)）同理：拒绝连接、不降级、不静默重建，
  并给出迁移路径。

### 6. 修复从哪来

现有的机制本身就是修复，本篇只是把它们**收进清单、编上号**：

| 机制 | 治什么 | 出处 |
|---|---|---|
| 盲扫 | 计数不对、索引库坏了：按槽状态重新认块、重算计数 | [格式 §9](format.md#r021) |
| 孤儿槽清理 | 删除崩在中途留下的槽 | [格式 §8](format.md#r021) |
| 由载体重建索引 | 索引与载体对不上：以载体为准重建 | [索引库 §013](index_db.md#r013) |

- 清单在 [`config/repair.txt`](../../config/repair.txt)：**一条一段、编号唯一**，实现照它。
- 代码落点 `src/oncasket/_repair/`：编号在 `ids.py`，一条修复一个模块；域外只调 `_repair`。
- 新增修复 = 清单加一段 + 发新号 + 加模块，**不改既有编号**（与路线图「条目只增不减」同调）。
