# 索引库（数据库）

>
> **事实依据**：[`config/index_db.sql`](../../config/index_db.sql)——表、列、取值以它为准，本文不另立、不改。
> 规范见[文档规范](../README.md)。

## <a id="r006"></a>006 逻辑块身份：正常 / 索引 / 被索引

- 决策状态：已定

- 同一个块实体，身份是**角色**不是属性（今天是学生，明天是工人，人还是那个人）。
- 身份由**表归属**表达，不用一列 `kind` 在总表上过滤：

| 表 | 收什么 | 谁维护 |
|---|---|---|
| `block` | 全部块（总表） | 提交路径 |
| `data_block` | 数据块的身份 | 引擎原生 |
| `index_block` | 索引块的身份（引擎原生提供的块） | 引擎原生 |

- 两张身份分表各为 `block_id` + `kind`；查询直接走分表，不在总表上往死里搜。
- `kind` = **它是什么这个问题本身**：`data_block.kind` 装「装了什么」（笔记 / 视频 …），
  `index_block.kind` 装「索引了什么」（属性 / title …）。取值**开放、不枚举、不加 CHECK**，为未来业务留余量。
- 身份行随总表行删（`ON DELETE CASCADE`）；连接必开 `PRAGMA foreign_keys = ON`，否则级联不生效。
- 「被索引」**不落点**：它是**关系**（谁指向谁），由索引块的指向表达，v0 不立第三张表；
  将来要做反向查询再立表，按 §012 走新指纹版本。

## <a id="r008"></a>008 索引库与索引形态选型

- 决策状态：已定

| 项 | 取值 |
|---|---|
| 载体 | SQLite（Python stdlib `sqlite3`） |
| 库文件 | `<hub>/index/index.db`（布局见 [hub 布局](hub.md)） |
| 日志模式 | `journal_mode = WAL` |
| 表模式 | `STRICT` |
| 外键 | `foreign_keys = ON`（连接必开） |
| 写入并发 | 由 park 级写锁串行；库侧不引入额外事务模型 |
| 额外依赖 | 无 |

- **事实依据为独立 `.sql`**：[`config/index_db.sql`](../../config/index_db.sql) 是机读的那一份，指纹直接从它算（见 §011）。
- 库文件与它的 WAL 边文件（`index.db-wal` / `index.db-shm`）**不是 park**：park 只认
  `<hub>/pack/**` 下的 `*.oncat`；目录布局见 [hub 布局](hub.md)。
- **SQLite 不锁版本、不单独引**：Python 换版可能换掉自带的 SQLite，Linux 上甚至可能链系统库。
  改为建库 / 打开时检测 `sqlite3.sqlite_version_info`，低于 **3.37**（`STRICT` 与所需 pragma 的下限）即拒绝。
  将来若真要某个 SQLite 专有特性，再议单独引（撞路线 025）。

## <a id="r009"></a>009 索引库为权威视角：提交点归索引

- 决策状态：已定

索引库是权威视角；**提交点 = `block.state` 翻到 `ok`**。

| # | 动作 | 落点 |
|---|---|---|
| ① | 生成块：算尺寸与属性 → 预算 `budget_slot` / `block_size` | 内存 |
| ② | 写索引行：`block_id` / `created_at` / 预算 / `global_hash` / `state = pending`；地址留空 | 库 |
| ③ | 找 park：先找能写的；能写的找不到 / 满了 / 坏了才新建 | 存储层 |
| ④ | 物理写：头槽 → 溢出槽\* → data 槽\*（末个 data 槽标 `结束`） | park |
| ⑤ | 校验：逐槽 `check` + 与库里的 `global_hash` 比对 | — |
| ⑥ | `state → ok` | 库 |
| ⑦ | 地址回流：`park` + `first_slot_id` | 库 |

- 两个**独立**的完成标记：`state`（写成功）、地址（回流成功）。
- 读可用 = `state = ok` 且地址非空；地址空而 `state = ok` → 扫描补地址（见 §013）。
- 因果不可倒：③ 在 ④ 之前，④ 才产生「在哪个 park、哪个区间」这个事实，所以地址只能最后写。
- **「返回」= 返回路径**：提交方法把结果（地址）或异常交回调用方，不是回退数据。
- **没有回滚**：本引擎不做数据版本管理（见 `config/format.txt` 头注），写入一经提交即为当前值；
  要改只能再走一遍「改前先读 → 改 → 写」，没有历史可退。
- **纯全局哈希**：block 视角、不分 slot；输入串 = 整块在载体上的全部字节（含各槽 `check`、含头槽自述区）。
  库侧列（`created_at`、预算）不在输入串内 → 重建可确定性复算。
- **改前先读**：任何修改先读回整块并验哈希，确认是目标块再动手。
- 崩溃判定：找得到 + 校验通过 = 成功；找不到 = 失败（GC 对账时清掉）。恢复可把 `pending` 提升为 `ok`；
  `state` 只表示「这次提交没走完」，不是终审。
- `state` 三值：`pending` / `ok` / `error`。
- `state` 的**唯一写者是存储引擎**：block 自己不写，数据库更不会自己写。
- 异常**不落库**：`error` 取值保留，但当前没有写入者（等接损坏登记 / 日志才启用）。
- 引擎**不内置日志子系统**：要日志的调用方自己重定向；引擎把日志**聚合成一个接口**给它（接口形态归路线 022）。
- **删除是写路径的镜像**：先动物理（头槽清零 → 其余槽清零），物理动完再动库（删行，级联清身份分表）。
  崩在中间 → 库里还有行、槽已不是「开始」→ 读取判失效，幂等重做。
- 槽级写协议与恢复策略（路线 019-020）另立篇，本篇引用不复制。

### 异常行为（穷举）

| # | 触发点 | 处置 |
|---|---|---|
| 1 | 参数不合法 / 预算算不出 | 抛异常，不落库 |
| 2 | ② 写索引行失败 | 抛异常；该次事务未提交，无残留 |
| 3 | ③ 找不到可写 park 且新建失败 | 行停在 `pending` → 抛异常；残留交 GC 对账 |
| 4 | ④ 物理写失败（半写） | 行停在 `pending` → 抛异常；半写块由逐槽 `check` 判废 |
| 5 | ⑤ 校验不过 | 行停在 `pending` → 抛异常 |
| 6 | ⑦ 地址回流失败 | 不算失败：不抛，扫描可补 |
| 7 | 读取：指纹不符 | 拒绝连接 + 抛异常（§012） |
| 8 | 读取：`state = pending` | 抛异常——这次提交没走完 |
| 9 | 读取：`state = error`（当前无写入者，保留取值） | 抛异常，带损坏点 |
| 10 | 读取：`state = ok` 但地址为空 | 不是错误：扫描补地址 |
| 11 | 读取：逐槽 `check` / `global_hash` 对不上 | 抛异常 + 报损坏点（**不落库**） |
| 12 | 读取：槽 `state` 不是「开始」（被删 / 被覆盖） | 抛异常；触发对账 |

- 原则：**能当场报的当场报**；不落库、不留痕——要留痕是调用方自己的日志。

## <a id="r010"></a>010 索引库冻结：内部资产，不向下游开放

- 决策状态：已定

- 不当底座：不承载下游 / 第三方业务，不做通用事务管理。
- 公开 API（路线 022）不暴露库文件、连接与表。
- §011 的守卫就是这条的手：结构对不上即不给用。

## <a id="r011"></a>011 索引库 schema 指纹与打开时守卫

- 决策状态：已定

每次连接前按序执行：

1. 提取结构（数据一律不取）：
   - 表：`PRAGMA table_info` 的列序（name / type / notnull / dflt_value / pk）+ `PRAGMA foreign_key_list`；
   - 索引：`PRAGMA index_list` 与 `index_info`（unique / origin / partial / 列序）；
   - 视图 / 触发器：其规范化 SQL（折叠空白）。
   - 排除 `sqlite_autoindex_*`（约束派生物，已由列与外键表达）。
2. 全序排序：条目按 (`type`, `name`) 的 UTF-8 字节序升序、大小写敏感；同类对象内按列序 / seqno。
3. 拼接：字段间 `\x1f`（US），条目间 `\n`。
4. 算 SHA-256（盐 `b"oncasket/index_db"`），与基准比对。

- 基准 = **从 [`index_db.sql`](../../config/index_db.sql) 算出的指纹**，升为引擎源码里的版本常量集合。
- 版本更新只增量追加新指纹，不删旧指纹。
- 提取项、排序、分隔、算法与盐写死一处。
- **生成与校验**：`config/index_db.sql` 是唯一写处；引擎侧的建库 DDL 与版本常量都由脚本从它**生成**，
  不人肉粘贴。生成物只增量追加新指纹、不删旧指纹；门禁在 pre-commit 与 CI 上 `--check` 比对。

## <a id="r012"></a>012 指纹不符后的处置

- 决策状态：已定

- 不匹配 = 库被动过 → **拒绝连接 + 抛异常**；不降级、不静默重建。
- 库的指纹高于本引擎声明的集合 → 同样拒绝连接。
- 结构一旦改动就换指纹：加列 / 加表 / 加索引都算新版本，旧库要么留在旧指纹里，要么迁移。
- §013 的重建**不是打开旧库修复**，而是丢弃旧库、另起新库。
- 版本类不符**不进修复策略库**——那是另一套 schema，猜不得；处置与迁移引导见[修复 §032](repair.md#r032)。

## <a id="r013"></a>013 载体自描述：索引可完全由载体重建

- 决策状态：已定

- 载体自带 `block_id`（头槽自述区）与逐槽 `check`，索引库全部内容可重建：
  盲扫 park → 判定完整块 → 复算 `global_hash` → 重建索引行与身份分表（地址、预算、时间由载体与扫描给出）。
- 找不到或校验不过的块不进库；崩溃残留由 GC 对账清理。
- 引擎**没有纠错能力**：只记录写入异常、block 损坏与损坏点，只提供读取损坏状态的 API，不自动修复。
  路线 019 的「恢复」= 检测 + 报告；路线 020 的「重建」= 重建索引与地址，不含数据恢复。
