# 空洞分配与死槽额度

> 域：内核 / 存储引擎 / 空间分配。对应路线图 [1.x 路线增量](../roadmap/1.x.md)。
>
> **事实依据**：[`config/format.txt`](../../config/format.txt)（park 头计数与 `slot_state`）、
> [`config/judge_db.sql`](../../config/judge_db.sql)（判定账本）——以它们为准，本文不另立、不改。
> 规范见[文档规范](../README.md)。

- 字段本身的定义（六个计数各自是什么）在[格式 §5](format.md#r021)；本篇只讲**怎么判、怎么算、怎么分配**。
- 盘上只有 `slot_state` 那五个魔数：**空 / 死不是盘上的状态，是判定结果**。

## <a id="r014"></a>014 空洞分配：预算 + 段选择策略（可配置）

- 决策状态：已定

### 1. 单位是段，不是槽

- **段** = 同一 park 内一段**槽 id 连续**、且 `slot_state = empty` 的槽。
- 分配与判定的单位都是段：一个块要么整段塞进某段，要么不塞——块不跨 park，也不跨段。
- **段表**是内存派生视图：优先由索引库的 `park` + `first_slot_id` + `budget_slot` 重建，
  库不可用时退回盲扫（[格式 §9](format.md#r021)）；**不落盘**，所以没有第二份真相要维护。

### 2. 挑剩下的就是死的——但要有证据

- **死槽不是另立一套阈值算出来的，是分配策略的余项**：按策略一路挑下去，最后**挑不中的段**就是死段。
  策略换一套，死的集合就换一套——判定与策略是同一件事的两面。
- 「空」= 当前策略下**挑得中**的段；「死」= 挑不中的段。两者盘上都是 `empty`，区别只在计数。
- **当场只能说「这轮没挑中」**：一个段没人要，可能是真死，也可能只是这轮没需求——盘上两者一模一样。
  所以判死要**连续多轮的证据**，证据落在账本上（见 [§015 第 1 节](#r015)）；没有账本，同一个 park
  每轮都白扫一遍，也说不清它是真死还是假死。
- 判死**只改计数、不改槽**；重判 = 重算段表，盘上一个字节不动。

### 3. 策略是配置型

引擎内置几套，调用方按 hub 选一套，**不把单一路线写死**：

| 维度 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `pick` | `best_fit` / `first_fit` / `worst_fit` | `best_fit` | 段选择：贴合最紧 / 最先够用 / 留最大的 |
| `dead` | `pessimistic` / `optimistic` / `off` | `pessimistic` | 死槽判定：见 [§015](#r015) |
| `K` 参数 | 分位数 / 样本窗口 / 样本门槛 | 见 [§015](#r015) | 只有 `dead = pessimistic` 用 |
| `M` 门槛 | 连续未命中轮数 | 见 [§015](#r015) | `dead = off` 时不判死、账本不写 |

- 落点：**hub 级配置**，走 OnConf 的 `hub.conf.json`（[hub 布局 §026](hub.md#r026)）；
  引擎不自造配置文件格式，也不把策略写进 park。
- 改策略 = 重算段表；`slot_live` / `slot_used` 不变，盘上不动。

### 4. 分配流程（`pick = best_fit` 时）

1. 段表按段长升序（同长按槽 id 升序）。
2. 取**满足需求的最小段**：`L ≥ 需求槽数` 且该段未判死——贴合最紧，剩下的还能再用。
3. 没有可用段 → 推进水线（`slot_live` 增长、文件懒长），从水线起连续取。
4. 水线顶到 `slot_num` 还拿不到连续段 → 按[格式 §6](format.md#r021) 新建 park。

- 需求槽数 = `⌈块位长 / slot_size⌉`；块位长 = 头槽 `slot_size` ＋ 各段自述属性 ＋ 块体。
- 计数关系见[格式 §5](format.md#r021)；`slot_num ≥ slot_live + slot_used + slot_dead` **不成立**——
  那会把 `used` / `dead` 算两遍。

### 5. `dead = off` 意味着什么

- 不判死：能放就放，`slot_dead ≡ 0`，碎段全记进 `slot_empty`。
- 代价是 `slot_empty` 变成**乐观数字**——账面有空间、实际挑不出一段连续的；额度 `D_max` 随之失去意义，
  park 会更早出现"账面还有地方却写不进去"。
- 想把碎段用掉只有一条路：**把块拆进多个不连续段**（碎片型 slot）。这撞路线 004 的连续性硬约束，
  是另一套约束体系——**不在 0.x，登记为未采用**；真要做，得新增路线，并先撤回或放宽 004。

## <a id="r015"></a>015 死槽判定与额度

- 决策状态：待裁（待定项见文末）

### 1. 判定要留痕：账本

- **当场只能说「这轮没挑中」，判死要有回溯**。段表（当前布局）可由载体与库推出来，所以不落盘；
  **账本（过去发生过什么）推不出来，必须落盘**——这两件事不是一回事。
- 落点：`<hub>/index/judge.db`（[hub 布局 §005](hub.md#r005)），与索引库同口径（SQLite / STRICT / WAL）。
  **独立于 `index.db`**：索引库是可丢弃重建的，账本不能跟着一起丢。
- 账本**可丢弃**：丢了等于判定回到冷启动（全按 `slot_empty` 算），不影响数据正确性——
  所以它不设指纹、不做迁移，结构变了直接重建。
- 记录单位是**槽区间**，不是段：

| 列 | 含义 |
|---|---|
| `park` / `seg_start` / `seg_len` | 区间：哪个 park、从哪个槽起、多长 |
| `misses` | 连续未命中轮数——**证据** |
| `verdict` | `empty` 挑得中 / `dead` 判死 |
| `first_seen` / `last_seen` | 首次 / 最近一次观测：Unix 秒，UTC |
| `revived` | 复活次数——**误判计数器** |

- 每轮分配扫段表时：未命中的区间 `misses += 1`、刷新 `last_seen`；命中的区间 `verdict = empty`、`misses = 0`。
- `misses ≥ M` → `verdict = dead`。**当场不判死**——`M` 轮电话都没接才下结论。
- 段会被占用切碎、被释放拼回，所以证据**绑区间、不绑段**：新段与旧记录**有交集**就继承其 `misses`
  （取交集里最大的那份）——这块空间被冷落了 `M` 轮，跟它后来怎么切无关。
- 读账本的人有三个：分配（跳过判死段）、GC 对账（路线 017，判死要有依据才上报）、读 API（报死槽与损坏状态）。
  `gc/report/*.json` 是账本的**定期汇总**，不是账本本身。
- **锁文件不做账本**：锁是「现在谁持有」，随取随放、随时可删；账本是「过去发生过什么」，只增不减。
  两样东西生命周期相反，混在一起等于谁都不敢删。

### 2. 非乐观预算

只从**实际数据**来，不拍脑袋：样本 = 本 hub 历史 block 的槽数（库里现成有 `budget_slot` 与实际占用）。

| 量 | 取法 | 方向 |
|---|---|---|
| `K` 最小块槽数 | `K = ⌈P90({ 历史块槽数 })⌉` | 取高分位 → 小段一律判死 → **少算**可复用空间 |
| `r` 死淘率上界 | `r = P90({ 各 park 的 slot_dead / slot_live })` | 取高分位 → **多算**将来的死淘 |

- **朝坏了想**：两处都取高分位，不取均值、不取下界。乐观取值（最小值 / 均值）会高估可复用空间、
  低估死淘，最终表现就是「写着写着 park 就满了」。
- 三档 `dead` 的差别：`pessimistic` 用 `K`（段长 `< K` 直接判死，不占 `M` 轮）；`optimistic` 取 `K = 1`
  （只按长度兜底，其余交给 `M` 轮证据）；`off` 不判死（见 §014 第 5 节）。
- 样本不足（历史 block < 64）时用缺省 `K = 4`、`r = 0`——还没观测到死淘就不预扣。
- `K` / `r` **不落盘**：它们是判定参数，随时可重算；重算 = 重扫段表。

### 3. 额度与触发

- 每个 park 的死槽额度 `D_max = ⌈r × slot_num⌉`；`dead = off` 时额度不适用。
- `slot_dead > D_max` → 该 park 报给批量 GC 触发（路线 016）；GC 与归档见路线 017。
- 死槽是**可逆判定**：样本更新、`K` 变小或判死后又被命中，都会让段回到 `slot_empty`——
  `revived` 就是误判计数，用来回头调 `M` 与 `K`。

### 4. 计数维护

- `slot_live` / `slot_used` / `slot_dead` / `slot_empty` 的**唯一写者是存储引擎**：
  写入与删除时顺手更新，GC 定期重算校正。
