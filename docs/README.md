# 文档规范

> 本页是仓库所有文档的**总规矩**。`docs/` 下每份文件都按它写；各层另有细则，但不得与本页冲突。
>
> 权威顺序：**`路线图 > 设计 > 代码`**。

## 1. 目录与分层

| 层 | 位置 | 装什么 | 细则 |
|---|---|---|---|
| 路线图 | `docs/roadmap/` | 做什么、挂哪篇设计、落在哪个版本 | [路线图结构说明](roadmap/README.md) |
| 设计 | `docs/design/` | 怎么做（口径）、为什么 | 本页 |
| 代码 | `src/` | 实现 | — |

## 2. 设计篇是两份文件

一个设计域 = 同名、同目录的两份：

- **事实依据**：结构文件 `<域名>.txt`（如 `format.txt`）。行式 DSL 写死字段、位偏移、取值，机器可读。
  实现照它，不照说明篇。
- **说明篇**：`<同名>.md`（如 `format.md`）。按节讲清这份结构怎么用、顺序是什么。
  **只解释事实依据，不另立字段、不改取值**；两者冲突，以事实依据为准。

## 3. 写法

- **不写解释性废话。** 一句能说完的不写一段；能上表的不写句子。
- **决定就是决定。** 不用「我认为 / 可能 / 建议 / 尽量」这类软话；没定的走第 4 条。
- **结构优先。** 字段用表、流程用有序步骤、状态用状态机、布局用代码块。
- **同名同义。** 术语一处定义、处处照抄；文档里的字段名与事实依据里的标识符逐字一致。
- **不复制。** 同一事实只写一处：路线图写落点、设计写口径、代码写实现，别处只链接。
- 日期用 ISO（`2026-10-09`）；正文中文，标识符英文。

## 4. 待定项

没定的不许混在正文里「暂定 / 待议」。**每篇末尾一节 `## 待定` 逐条列**：待定项、卡在哪、谁拍。
对应路线条目的 `决策状态` 保持 `待裁`，直到待定清空。

## 5. 版本标记

带结构的设计文件，首行固定两行：

```text
encoding: utf-8 version: <sha256>
endian: little
```

`version` 是**内容指纹**，不是数据版本（本引擎不做数据版本管理）。改完必须重盖，漏盖即门禁红：

```bash
python scripts/stamp_version.py docs/design/format.txt
python scripts/stamp_version.py docs/design/format.txt -c   # 门禁：不符退出 1
```

## 6. 关联

- 路线图条目用 `[篇名 §<路线ID>](相对路径#r<路线ID>)` 指向设计篇的对应节；
  没有设计篇就写「该域尚无设计篇」——**没链接就是没设计**。
- 设计篇内按 `<a id="r<路线ID>"></a>` 锚点分节。
- 编号、版本分配、勾选框等细则见[路线图结构说明](roadmap/README.md)。
