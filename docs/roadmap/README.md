# 路线图结构说明

> 本页是 `docs/roadmap/` 下各份路线图的**格式与维护口径**。路线图文件只装数据
> （路线增量 + 版本分配），怎么读、怎么写、怎么改都在这份里。
>
> 路线图在权威顺序里居首：**`路线图 > 设计 > 代码`**。

## 三条硬规则

1. **平行任务，禁止依赖。** 路线图里的条目彼此平行，**不得出现任何依赖表述**：不写先后、
   不写派生、不写引用（「由 024 推出」「见 017」「等某条做完再动」都算违规）。
   版本分配是**落点**，不是次序，也不是依赖。沿革与理由（「因为 A 所以 B」）写进设计篇，
   不回流到本页。条目之间一旦咬住，改动就会连锁，先例一开收不住。
2. **口径只认设计篇。** 路线图**禁止写任何设计口径**（怎么做、定成什么样、为什么这么定）。
   每条只说「做什么、关联哪篇设计、落在哪个版本」。`设计关联文件` 是「有设计」的**唯一凭据**：
   - **没有关联就是没设计**——代码写了不算，设计篇写了但没关联也不算；
   - 关联到哪一篇，口径就以那一篇为准。
3. **分层拆解，从大到小。** 条目不平铺，按「层 → 模块 → 子模块 → 条目」嵌套：先大路线
   （整体），再小路线（对象与过程），最后落到条目。子模块按内容命名（如 `整体形态与边界`、
   `物理结构：slot / park`、`逻辑块`、`索引库（数据库）`、`空间回收（GC）`、`写入与恢复`），
   深度够用即止，不为凑对称强加层级。嵌套只表归属，不代表依赖或先后。

## 范围

- 每份路线图只管一条版本线（`0.x.md` 管 0.x）。下一条线另开一份（`1.x.md`）——
  按版本序列切分才不会庞大无比；每条线到它为止，此后只维护未落定版本，不再增量。
- **只记开发路线，不记修复路线**：缺陷修复、补丁类 issue 一律不上路线图。条目只由**主动加入**的
  能力与决策构成，不是"做过多少"的流水账；版本号也不会因修复而虚涨。
- **上下两块**：`## 路线增量` 收全部条目（唯一事实源），`## 版本分配` 按版本关联条目 ID。
- **路线增量**是增量性质的：新决策随时加上去，完成就打勾。条目按归属层层嵌套
  （层 → 模块 → 子模块 → 条目）；嵌套只表归属，不代表依赖或次序。
- **路线ID**：三位序号（`001`、`002`…），**全局唯一、号不复用**；**号跟着文档走**——沿
  `## 路线增量` 自上而下、深度优先，见到的第 n 个条目就是第 n 号，编号顺序与阅读顺序一致。
  新增条目接在末尾发新号；条目改名不改号；**重排层级后整份重编号**，不留空号、不倒序。
  号在全部路线图文件里**连号**（`1.x.md` 接 `0.x.md` 的最大号往下），故 `grep 001` 不会撞上第二份。
- **条目名**只写「做什么」，不写做法；做法进设计篇。

## 条目卡片

每个条目固定六行，缺项留空不删——字段是栏位，不是正文。

- `决策状态`：只写状态词——`已定` / `待裁` / `未定` / `未来项` / `已废弃`。
  破折号后**不接口径**：待裁条目的备选方案、已定条目的具体结论，一律写进设计篇。
- `设计关联文件`：口径在哪一篇。写 `[<设计篇名> §<路线ID>](<相对路径>#r<路线ID>)`；
  尚无设计篇时写明「该域尚无设计篇」（即没设计）。
- `分配实现版本`：落在哪个具体版本；未定写 `待定`，废弃写 `已废弃`。
- `具体实现文件`：代码落在哪；尚未建就写明缺哪一层，不写「无」；不写做法。
- `关联 issues / PR`：GitHub 编号；`未合` 标注尚未合并的 PR。**不得**用于条目之间的互相引用。

## 勾选框

`- [x]` 表示这条**不在待办里**——收口了，或是废弃了；两种情形靠括号分辨。

- **收口**：条目名后不加注。
- **废弃**：曾经定过、现已不再做，且**既无代码也无设计**的条目——**不删**，打勾并在条目名后注 `（已废弃）`。
  留痕是为后人不再重新提一遍。

## 版本分配

每个版本号下列该版本关联的条目 ID。版本只有两种状态：

- **已发布**：标题后注 `（已发布）`——写死，此后不再变动。
- **未落定路线**：标题后注 `（未落定路线）`，或什么都不写（默认即是）。分配仍可调整——
  改分配是**纯增量**（条目只增不减、版本号只增不减），不视为推翻。改分配只改落点，
  不改条目之间的平行关系。

废弃条目汇总在 `### 已废弃`，不占版本号。

## 条目模板

新增条目照抄下面六行，字段顺序不变。

```text
> 路线ID:
> 决策状态:
> 设计关联文件:
> 分配实现版本:
> 具体实现文件:
> 关联 issues / PR:
```
